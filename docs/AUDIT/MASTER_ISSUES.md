## 3. Developer System Invariant Checklist (The 15 Questions)

Every feature, query, and entity must pass all 15 invariant gates before implementation:

1. **Entity Definition:** What is the exact data model, PK, and tenant foreign key?
2. **Ownership:** Which organization and project own this entity?
3. **Read Access:** Who can view this entity, and what fields are masked for clients/vendors?
4. **Creation Gate:** Which role can create it, and under what pre-conditions?
5. **Mutation Gate:** Who can edit it, and what state must it be in?
6. **Approval Gate:** Who can approve it, and is self-approval strictly prevented (SoD)?
7. **Deletion Rules:** Soft-delete vs. Restricted vs. Cascade — what happens to child records?
8. **Lifecycle States:** What are the exact valid state transitions and terminal states?
9. **Event Outbox:** What domain event is published when this entity mutates?
10. **Audit Trail:** What tamper-evident record (old state, new state, actor, timestamp) is logged?
11. **Offline Behavior:** Can field engineers draft/read this entity in offline IndexedDB?
12. **Concurrency / Race Conditions:** What happens if two users mutate/approve simultaneously?
13. **Failure Recovery:** If the network or API fails, what is the user-safe rollback/retry state?
14. **Unauthorized Access:** If a user attempts direct API access without permission, does RLS reject with 403/404?
15. **Cascade / Purge Safety:** What happens when the parent organization or project is archived?

## Architecture — layer by layer

### Layer 1 — Edge Functions (network boundary)

Three new EFs, all sharing the `_shared/` utilities.

| EF | Purpose | Idempotency strategy | Retry strategy |
|----|---------|----------------------|----------------|
| `whatsapp_dpr_send` | Sends a DPR (voice + photo + text + anchor URL) to a promoter's WhatsApp via Meta Cloud API | `client_token` (UUID generated by mobile) deduped via `dpr_delivery_log` PK | 3 attempts with exponential backoff (1s, 4s, 16s); on final failure write `status='failed'` row |
| `voice_transcribe` | Telugu/Hindi voice → text via Bhashini API primary, AWS Transcribe fallback | `audio_sha256` deduped via `voice_transcripts` PK; returns cached transcript on repeat | 2 attempts on Bhashini, then 2 on AWS, then return 503 |
| `buildnow_anchor` | Mirror a project's BuildNow status into our DB; generate verifiable badge URL | `(project_id, sync_date)` upsert key | 1 attempt — eventual consistency is fine |

Shared utilities:
- `_shared/whatsapp_client.ts` — Meta Cloud API v18 wrapper with token validation + rate-limit guard.
- `_shared/idempotency.ts` — generic upsert-by-token helper used by all 3 EFs.
- `_shared/retry.ts` — exponential backoff helper.

### Layer 2 — Lib modules (pure, browser + Deno compatible)

| Lib | Browser | Deno EF | Purpose |
|-----|---------|---------|---------|
| `voiceTranscribe.js` | ✅ for offline cache lookup | ✅ for provider switching | Selects Bhashini vs AWS vs mock. Records confidence per result. |
| `offlineQueue.js` | ✅ primary user | ⛔ N/A | IndexedDB-backed pending-write queue. Drains when network returns. |
| `buildnowAnchor.js` | ✅ for badge UI | ✅ for sync job | Same hashing + URL generation in both layers (matches `blockchainAnchor.js` 3-way invariant pattern). |

Every lib has a `mockAdapter` for tests (matches `blockchainAnchor.js`
+ `cashfree.js` precedent — tests don't hit real providers).

## Interface contracts (the bits other developers / future-Claude need)

### `voiceTranscribe.js`

```js
// transcribe(audioBlob: Blob, { lang: 'te'|'hi'|'en', provider?: 'auto'|'bhashini'|'aws'|'mock' })
//   → { ok: true, text: string, confidence: number 0-1, lang: string, provider: string, audio_sha256: string }
//   → { ok: false, error: string, provider_tried: string[] }
//
// Behavior:
//  - 'auto' (default): try Bhashini → AWS → mock. Mock only in test mode.
//  - 'mock': returns canned response from test fixtures.
//  - Caches by audio_sha256 — re-submission returns cached result with .cached=true.
//  - On all-providers-failed: returns ok:false with provider_tried list for debugging.
```

### `offlineQueue.js`

```js
// enqueue(key: string, payload: any, { kind: 'dpr'|'voice'|'photo' }): Promise<string>
//   → IndexedDB-stored item with retry_count=0, status='pending'
//   → returns the queue item id
//
// drain(networkOnline: boolean, sendFn: (item) => Promise<{ok, error?}>): Promise<DrainStats>
//   → walks all 'pending' items, calls sendFn for each
//   → exponential backoff on retry (1s, 4s, 16s, 64s)
//   → returns { sent, failed, deferred }
//
// queueDepth(): Promise<{ total: number, by_kind: Record<string, number> }>
//
// Behavior:
//  - All persistence in IndexedDB (sitetrack-offline-v1 db).
//  - Items > 7 days old AND status='failed' are auto-deleted.
//  - Drain is idempotent — multiple drain() calls in parallel safely no-op.
```

### `buildnowAnchor.js`

```js
// fetchProjectMetadata(buildnowProjectId: string): Promise<{ ok, metadata, source: 'api'|'scrape'|'cache' }>
//   → tries BUILDNOW_API_TOKEN env path first
//   → falls back to scrape (Playwright on Deno) if API access denied
//   → caches result in buildnow_anchors table
//
// generateBadgeUrl(projectId: string, dprId: string): string
//   → deterministic URL like https://buildnow.telangana.gov.in/verify?p=...&d=...
//   → DOES NOT call BuildNow; generates the URL builders can verify
//
// computeAnchorHash(dprPayload: object): string
//   → sha256 of canonical-JSON-serialized payload
//   → same algorithm in browser + EF (3-way invariant — matches blockchainAnchor pattern)
```

## Idempotency + retry semantics

All 3 EFs share the contract: **the client generates a UUID
(`client_token`) and includes it in the request**. The EF UPSERTs by
that token. If the client retries the same payload, the EF returns
the original result.

This is the same pattern that's already shipped in `cashfree_events`
(migration 31) — so we re-use the helper there.

Retry policy:
- Mobile client: 3 attempts at 5s / 30s / 5min (handles flaky 2G).
- EF → upstream (Meta / Bhashini): handled inside EF with 3 attempts
  exponential.
- EF → DB: 1 attempt — if Postgres is down, the EF fails the request;
  client retries.

## Risks + mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|-----------|
| Bhashini API access denied or rate-limited beyond pilot tier | Medium | AWS Transcribe fallback (paid; ~₹0.02 per 15-sec clip). Per-org budget cap. |
| BuildNow Telangana API access denied to private vendor | High | Scrape-fallback documented; relationship-building with TG IT dept Sprint 3. |
| Meta WhatsApp Business token revoked mid-pilot | Medium | Dual-token strategy: founder personal token + dedicated business token. Auto-failover. |
| Voice transcription accuracy < 85% in basement parking with site noise | Medium | Pre-pilot: capture 20 phrases at 2 real sites + measure with both Bhashini + AWS. Pick the better. Manual correction UI for supervisors. |
| Telugu UI broken on Rs 8,000 Android | Medium | Bake-test on Realme C53 + Redmi A2+ during Sprint 2 Week 1. |
| Pilot supervisors abandon flow after Day 3 | High | Founder-led 90-min on-site activation + WhatsApp support directly to supervisor (not promoter). Per `docs/sales/PILOT_ONBOARDING_RUNBOOK.md`. |
